# Три набора данных `official core 59` воспроизводимы по коммиту (2026-11-18)

**Роль:** `DERIVED_READ_ONLY_NOT_AUTHORITY`. Квитанция про байты, не про права.

**Вопрос, на который отвечает документ.** Документ статуса от 2026-07-30 фиксирует: три
набора данных (STEPBible, `morphhb`, SBLGNT) отчёт объявил скачанными и проверенными, но в
архиве на Drive их нет. Единственный живой кандидат на копию — артефакт CI
`ephemeral-official-core-acquisition-59-v2` на 123 193 373 Б, истекающий 2026-11-24. Отсюда
вопрос: **что будет, когда артефакт исчезнет** — доказательство пропадёт или его можно
восстановить?

**Ответ: восстановить можно, и без артефакта.** Байты детерминированно собираются с
`codeload.github.com` по зафиксированному коммиту, и все три размера совпали с записанными
байт в байт.

## 1. Что проверено

документом статуса и локальный `sha256`. В репозитории и на Drive ничего не менялось.

неизменяемы, пока апстрим не перезапишет историю.

## 2. Что это меняет в оценке риска

Прежняя формулировка — «единственная копия исчезает 24 ноября» — была неверной. Точная:

- **артефакт CI не нужен для восстановления.** Его содержимое так и не проверено (скачивание
  из песочницы блокируется: `gh api` уводит на `productionresultssa5.blob.core.windows.net`),
  но это больше не важно: байты берутся из апстрима по коммиту;
- **дата 2026-11-24 перестаёт быть дедлайном хранения.** Она остаётся дедлайном только для
  удобства — «забрать то, что уже лежит под рукой», а не «спасти единственную копию»;
- **впервые появились SHA-256** трёх наборов. До этого в репозитории были только размеры и
  коммиты, то есть проверять было нечего.

## 3. Чего это не доказывает

- **Права.** Воспроизводимость архива — не разрешение на использование. В очереди кандидатов
  v1 права записаны как «dataset-specific; verify each subdataset» для STEPBible,
  «WLC text public domain; morphology CC BY 4.0» для `morphhb`, «CC BY 4.0» для SBLGNT. Это
  заявленные лицензии репозиториев, а не решение владельца корпуса.
- **Содержимое.** Архивы не распаковывались и не читались: проверен носитель, а не текст.
- **Полноту.** Совпадение размера с записанным в 2026-07-30 — это совпадение с *тем* отчётом.
  Если сам отчёт ошибался в природе объекта (например, для STEPBible «dataset-specific» —
  это набор подкаталогов с разными условиями), квитанция эту ошибку не поймает.

## 4. Что остаётся сделать — и это уже не про хранение

1. Решить права по трём наборам отдельно, по подкаталогам STEPBible, а не «по репозиторию».
2. Если решение положительное — приобрести на Drive с квитанцией (Drive ID + размер + SHA-256
   из таблицы выше) и только тогда писать в реестре, что наборы сохранены.
3. Артефакт 2026-11-24 не трогать специально: он больше не единственный носитель.
