# Матрица определения прав: 22 объекта (2026-11-18)

**Роль:** `PROPOSAL_NOT_AUTHORITY`, производный документ. Здесь **не снимается ни один HOLD**
и не меняется ни один `rightsState`: матрица раскладывает 22 объекта запроса по слоям, где
права действительно возникают, и по цене закрытия. Решение принимает владелец.

**Что попало в матрицу:** 22 объекта, которые в docs/research/holds/HOLD_INVENTORY.md §4.7 держат только права/публикацию и требуют установления прав. Матрица не меняет rightsState и не снимает ни один HOLD.

**Фильтр отбора:**

`holds ⊆ {RIGHTS_HOLD, PUBLICATION_HOLD} ∧ accessState=FULL_OBJECT_VERIFIED ∧ locatorState=EXACT_LOCATOR_VERIFIED ∧ rightsState ∈ {RIGHTS_UNKNOWN, PERMISSION_REQUIRED}`

Это тот же фильтр, что в `render_hold_inventory.py::check_decision_only_holds()`;
совпадение наборов проверяется скриптом `scripts/render_rights_matrix.py --check`.

## 1. Почему «права неизвестны» — не одно и то же в 22 случаях

Права возникают на четырёх разных слоях, и HOLD стоит на разных:

| Слой | Что это |
|---|---|
| `work` | Само произведение: автор, дата, срок охраны. |
| `edition` | Конкретное издание и его аппарат (критическое издание, перевод, редактура). |
| `scan` | Цифровой объект: скан, транскрипция, OCR и условия оцифровщика. |
| `site` | Страница-публикатор: вёрстка, примечания, корпус сайта. |

Объект XVI–XVII вв. в общественном достоянии и **та же страница** с современным переводом — это
два разных правовых объекта. Пока слой не назван, «`RIGHTS_UNKNOWN`» читается как
неизвестность там, где на самом деле известна неполнота записи.

## 4. Проверка оцифровщика: почему у восьми узлов Pusey не появилось основания прав

Эта часть — единственная, где 2026-11-18 выполнялась внешняя проверка, и она **не** дала
основания снять HOLD. Наоборот, она объяснила, почему `RIGHTS_UNKNOWN` здесь честен.

Репозиторий сканов: `OpenGreekAndLatin/2013-11-26-23-24_operacyrilli03cyriuoft_jp2_OCT7_rev`. Метод: `gh api repos/<repo> (license) и gh api repos/<repo>/contents/ (список корня); только чтение`.

| Что проверялось | Результат |
|---|---|
| Поле `license` в GitHub API | `None` |
| Содержимое корня репозитория | 2013-11-26-23-24_operacyrilli03cyriuoft_jp2_OCT7_rev.book (dir) |
| Файл LICENSE | отсутствует |
| README | отсутствует |

В репозитории уже есть запись о лицензии OGL — `ИСКУПЛЕНИЕ/evidence/source_controls_wave7_2026-11-03.json`, ключ
`rights.openGreek`:

> Aggregate CC BY-SA 4.0; project OCR additionally CC BY 4.0 per LICENSE. Selected row license=PD describes underlying edition, not automatic release of all digital components.

Это утверждение относится к корпусу OGL, у которого LICENSE есть. Для репозитория сканов оно не подтверждено и не опровергнуто: там LICENSE отсутствует.

Контраст: `OpenGreekAndLatin/First1KGreek` действительно заявляет `CC-BY-SA-4.0`. Переносить эту лицензию на репозиторий сканов было бы
выдумкой: лицензии там нет вовсе, и отсутствие лицензии не читается ни как разрешение,
ни как запрет.

Отсюда два честных пути закрытия восьми узлов — и оба требуют владельца, а не поиска:

1. **Политика faithful reproduction.** Издание 1872 г. вне охраны (колофон осмотрен визуально),
   оцифровщик прав не заявляет. Решение о допустимости воспроизведения такой страницы —
   политика владельца с записанным обоснованием, а не «права установлены».
2. **Переприобретение из источника с явным заявлением о правах.** Те же страницы нужно
   получить там, где статус объекта написан словами; тогда основание прав появляется
   из первичного заявления, а не из рассуждения.

## 5. Границы

- Это не юридическое заключение и не снятие HOLD: rightsState меняет только владелец.
- Классификация опирается на дату и природу объекта, записанные в репозитории, а не на внешнюю проверку сроков охраны по юрисдикциям.
- Внешние проверки выполнены только по api.github.com; archive.org, rca.org, opc.org, frcna.org, anglican.ca, catholic.com в этой сессии не открывались.
- Отсутствие заявленной лицензии у оцифровщика не читается ни как разрешение, ни как запрет.

Воспроизводимость: `python3 scripts/render_rights_matrix.py --check`.
