# `docs/research/holds/` — что здесь лежит и что из этого ждёт решения

Этот каталог — не источник права и не реестр. Здесь лежат **датированные измерения** HOLD-контура:
сколько записей держат HOLD, сколько объектов не приобретено, кто видит файлы на Drive, какие права
установлены, а какие нет. Ни один документ отсюда не снимает и не ставит HOLD. Всё, что меняет
состояние, лежит в реестрах проектов (`SUNO_HYMNS/data/`, `1_PETER_BOT/data/`, `ИСКУПЛЕНИЕ/*/data/`),
а гейты проверяют именно их.

**Дата среза:** 2026-11-18. Числа меняются при любом изменении реестров — это не константы.

## 2. Что решено, а что ждёт владельца

**Решено и проверено гейтами:** инвентарь собирается детерминированно; матрица прав и повторяемость
ядра сверяются своими `--check`; недо-приобретённые записи делятся на «объявляют объём осмотра» и
«молчат», и молчащих ноль; доступ к 48 объектам Drive проверен и у всех единственное разрешение —
владелец `oldpoet2025@gmail.com`.

**Ждёт решения владельца (данные я не менял):**

1. **11 записей SUNO без HOLD** (`SRC-PHOS-BASIL-DSS` и ещё десять) — все `PUBLICATION_ELIGIBLE`.
   Выбор между «выставить `EVIDENCE_HOLD`» и «признать, что частичное чтение обеспеченного текста
   HOLD не требует» задаёт смысл остальных 104 записей. → `UNDER_ACQUIRED…` §6.1.
2. **`bigg_icc`** — `LINK_ONLY`, права чистые, объект живёт только ссылкой на archive.org. Что
   уместнее: `EVIDENCE_HOLD` или `ARCHIVE_HOLD`. Одна запись, но она образец. → §6.2.
3. **44 записи 1 Петра** — та же разница конвенций без отдельного дефекта в каждой. → §6.3.
4. **83 записи, называющие HOLD прозой** — оставить прозу прозой, перевести объектные токены в поля
   или печатать оговорку рядом с инвентарём. → §10, режим `--no-holds-field` и `audit_prose_holds.py`.

**Ждёт не решения, а работы (внешней):** сверка каталога `SINICHKIN — MASTER FILE CATALOG` (5 941
строка) с Drive по SHA-256 — сделано 6 сравнений из 5 941; визуальная сверка Pusey II с. 294–296
(кадры 306–308) для `C-25` — нужен человек со сканами, OCR-путь уже описан в
`ИСКУПЛЕНИЕ/evidence/PUSEY_II_294_296_OCR_LOCATOR_2026-11-18.md`.

## 3. Как это проверяется

```bash
python3 -B scripts/run_research_gates.py            # 5 гейтов + 4 информационных счётчика
python3 -B scripts/audit_hold_coverage_gaps.py --summary     # 51 и их раскладка
python3 -B scripts/audit_hold_coverage_gaps.py --no-holds-field  # 52 без поля holds
python3 -B scripts/audit_prose_holds.py --summary            # 83 с HOLD в прозе
python3 -B scripts/audit_hold_coverage_gaps.py --promotion-gaps   # 1 PROMOTE с пробелом
```

Первый запуск требует полного клона: на shallow-клоне гейт целостности корпуса откажется проверять
`commitTimeChecks`, и это правильно — проверка, которая ничего не сверяет, не должна называться PASS.

## 4. Чего здесь намеренно нет

- **Правок реестров.** Ни один документ каталога не меняет `holds`, `rightsState` или `publicationState`.
- **Скачанных объектов.** Всё, что здесь сказано про байты, сказано по метаданным Drive, а не по
  содержимому файлов; где сверка шла по SHA-256, это указано отдельно.
- **Слов «утрачено» и «отсутствует» о выпусках.** По правилу самого архива пропущенный выпуск сначала
  попадает в очередь `TO DOWNLOAD` и не считается утраченным без библиографической проверки.
