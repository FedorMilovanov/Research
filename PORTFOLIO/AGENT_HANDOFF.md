## 1. Цель и границы

**Цель.** В каждом репозитории сделать три вещи:

1. Человек за первые 20 секунд понимает: что это, кто это сделал, работает ли оно и где посмотреть.
2. Агент, попавший в репозиторий, понимает: где правда, что можно трогать, что нельзя и как проверять.
3. Поиск (GitHub и Google) находит репозиторий по осмысленным словам: описание, topics, первые абзацы README, глоссарий.

**Не цель.** Не переписывать продуктовую логику, не менять утверждения о фактах, не «улучшать» код, не трогать governance, не менять лицензии без владельца, не создавать видимость работы (десять мелких PR вместо одного осмысленного).

**Приоритет исполнения:** сначала то, что видит внешний читатель (README, описание, topics), затем то, что видит агент (AGENTS.md, ARCHITECTURE), затем глубина (CASE_STUDY, GLOSSARY, RUNBOOK).

## 2. Жёсткие правила

1. **PR, а не прямой push в `main`.** Один репозиторий — одна ветка — один PR на одну волну. Исключение: репозитории, где владелец явно разрешил иначе (смотри их собственный `AGENTS.md`).
2. **Уважай локальный контракт.** В `Research` действует модель authority: новый документ не становится authority автоматически. В `video-channel-manager` и `gb-is-my-strength` есть свои `AGENTS.md` — они главнее этого файла в вопросах процесса.
3. **Не переписывай историю.** Никаких `filter-repo`, `rebase -i` по опубликованным ветвям, force-push в `main`.
4. **Не трогай:** `.github/workflows` без необходимости, секреты и `.env`, `data/*authority*`, `CURRENT_AUTHORITY.md`, `AGENT_RULES.md`, продуктовый контент (тексты статей, переводы, стихи), миграции БД, лицензии.
5. **Не выдумывай факты и цифры.** Все числа берутся из `METRICS.csv` (и `CLAIMS.csv`) с датой. Если цифра неизвестна — не пиши её.
6. **Не приписывай владельцу чужое.** Движок `vosk-tts` — Apache-2.0, чужой. Музыка — Suno по его текстам/промтам. Кондитерское дело — Виктория Милованова. Формулировки ниже уже учитывают это.
7. **Не публикуй ничего в соцсети и не вызывай провайдерские API.** Только файлы и PR.
8. **Не добавляй бейджи, которых нет** (coverage без отчёта, «build passing» на репозитории без CI).

### 3.2. `OWNER.md` в корне (обязательно)

Полная карточка: кто, чем занимается, что именно сделано в этом репозитории, что сделано ИИ, как связаться, как ссылаться. Максимум 60 строк. Шаблон:

```markdown
# Владелец и авторство

**Фёдор Милованов** — продуктовый инженер, технический редактор, оператор ИИ-производства.
Санкт-Петербург, Россия. [email] · [Telegram] · [GitHub](https://github.com/FedorMilovanov).

## Что сделано лично
- постановка задачи и границы продукта;
- архитектура и машинные контракты (см. раздел «Где правда» в README);
- редактура, приёмка, публикация, эксплуатация;
- разбор дефектов и превращение их в проверки.

## Что сделано ИИ под управлением владельца
- значительная часть кода и документации;
- генерация медиа (музыка — Suno, изображения и видео — генеративные модели);
- черновики статей и описаний с последующей человеческой редактурой.

## Чужая работа, использованная легально
- (перечислить: движки, словари, библиотеки, шрифты — с лицензиями и ссылками)

## Как ссылаться
«<Название проекта>, автор — Фёдор Милованов, <URL>».
```

### 3.3. Структура README (обязательно, в этом порядке)

```markdown
# Название
> Блок владельца

**Одна строка: что это и для кого.**

| Статус | Живой адрес | Стек |
|---|---|---|
| production / beta / архив | https://… | Astro · Python · … |

## Что это
3–6 предложений. Кто пользователь, какую задачу решает, чем отличается.

## Что уже работает
Список конкретного: страницы, команды, функции. С числами из METRICS.csv и датой среза.

## Как это устроено
5–8 пунктов архитектуры + ссылка на ARCHITECTURE.md.

## Где правда (для агентов)
- какой файл/реестр является источником истины;
- какие проверки обязательны перед PR;
- что запрещено менять.

## Проверки
Команды, которые реально запускаются в CI.

## Для тех, кто ищет
Глоссарий ключевых терминов проекта (5–10 строк) — это одновременно помогает людям и индексации.

## Лицензия и права
Код / контент / медиа — раздельно.
```

## 5. Тексты, которые нельзя менять на «улучшенные»

| Что | Почему |
|---|---|
| «Исследовательская закрытость ≠ разрешение на публикацию» | это нормативная формулировка проекта |
| Утверждения о правах на изображения и медиа | юридический смысл |
| Даты, имена, названия произведений и авторов | фактология |
| Формулировки в `docs/operations/*` о состоянии провайдеров | операционная истина |
| Правила вида «never_replay», «single-writer», «postcondition» | это и есть технология |

## 6. Definition of Done

Репозиторий считается обработанным, если:

- [ ] README открывается блоком владельца и одной строкой «что это».
- [ ] Есть таблица «статус / живой адрес / стек» и раздел «что уже работает» с числами и датой среза.
- [ ] Есть раздел «где правда (для агентов)» с 3–6 пунктами и ссылками на файлы.
- [ ] Есть `OWNER.md` с разделением «сделано лично / сделано ИИ / чужая работа».
- [ ] Есть `.mailmap`, и `git shortlog -sne --use-mailmap` показывает владельца одной строкой.
- [ ] Есть `ARCHITECTURE.md` (для 6 репозиториев) или раздел «как устроено» (для остальных).
- [ ] Ни одной выдуманной цифры, бейджа или ссылки.
- [ ] Все ссылки проверены (`curl -I` или ручное открытие), нет 404.
- [ ] CI зелёный на PR; если что-то падало — в описании PR сказано, что и почему.
- [ ] Дифф не превышает ~600 строк на репозиторий, кроме случаев, когда владелец разрешил больше.
- [ ] В описании PR — 5 пунктов: что сделано, что не тронуто, какие цифры использованы и откуда, как проверено, что осталось.

## 7. Протокол PR

**Заголовок:** `docs(owner): README + OWNER + ARCHITECTURE для <repo>` — или `docs(readme): ...`.

**Тело:**

```markdown
## Что сделано
- ...

## Что не тронуто
- governance/authority, контент, workflows, лицензии

## Источники цифр
- METRICS.csv (дата среза 2026-11-01), MEDIA_PRACTICE.md, README репозитория

## Как проверено
- ссылки открыты, `npm run validate` / `pytest -q` / grep по цифрам

## Осталось
- ...
```

**Правила:** один PR — одна волна; не смешивать документацию и код; не пушить в `main` напрямую; при конфликте с локальными `AGENTS.md` — соблюдать локальные.

## 9. Стоп-условия

Остановиться и спросить владельца, если:

- правка требует изменить нормативный документ (`CURRENT_AUTHORITY.md`, `AGENT_RULES.md`, `docs/operations/current-state.md`);
- обнаружилось расхождение фактов (например, число видео не совпадает со снимком) — не «исправлять», а вынести в PR отдельным пунктом;
- возникает вопрос лицензии;
- в репозитории есть незакоммиченные изменения или открытый PR, который пересекается по файлам;
- требуются права на запись к провайдеру (YouTube/VK/Telegram/Instagram) — это вообще вне задачи.

## 11. Проверка результата владельцем (5 минут на репозиторий)

1. Открыть README на телефоне: понятно ли, что это, за первые два экрана?
2. Найти в README строку про авторство и ссылки — работают?
3. Открыть `OWNER.md`: нет ли присвоения чужой работы?
4. Проверить одну цифру по `METRICS.csv`.
5. Посмотреть дифф: не изменилось ли что-то в контенте, workflow или лицензиях.
