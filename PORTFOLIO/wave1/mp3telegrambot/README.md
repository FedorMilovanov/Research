# Волна 1: `mp3telegrambot` — изменений не требуется

Статус: **репозиторий уже на базовой линии**. Это результат проверки, а не отказ
от работы: предложение «поставить контур» здесь означало бы дублирование уже
существующих гейтов.

## Поэлементная проверка

| Элемент контура | Состояние | Где именно |
|---|---|---|
| Сканирование секретов | есть, блокирующее, по полной истории | `.github/workflows/secret-scan.yml`, джоб `gitleaks`, `fetch-depth: 0`, недельный `schedule` |
| Конфигурация правил | есть | `.gitleaks.toml` |

Проверено по клону: `1 120` отслеживаемых файлов, `20` workflow-файлов,
`SECURITY.md`, `.gitleaks.toml`, `.github/dependabot.yml` — все на месте.

## Почему ничего не добавлено

1. **Джоб гигиены workflow** дублировал бы `pytest`-набор, причём в более слабой
   форме: тест mp3 знает точные SHA и версии и падает на любом неотревьюженном
   действии, шаблонный скрипт проверяет только форму 40-hex.
2. **Отдельный secret-scan** уже есть и уже блокирующий на `schedule`, в отличие от
   `Research`, где недельный прогон осознанно сделан неблокирующим (полная история
   там содержит архивные идентификаторы, дающие ложные срабатывания на широких
   шаблонах).
3. **`SECURITY.md`** уже существует, переписывать его под шаблон значило бы стереть
   специфику проекта (пять внешних сервисов, 174 переменные окружения).

## Что остаётся незакрытым (и почему это не чинится одним PR)

* Зелёность прогонов не измеряется: доля успешных запусков по-прежнему `UNPROVEN`,
  потому что `actions/runs` зажимает `total_count` на 2 500.
* Branch protection недоступен для чтения токеном (`403`), поэтому правило
  «нельзя пушить в `main` напрямую» остаётся непроверенным извне.

Обе строки — ограничения наблюдаемости, а не отсутствующие контроли в репозитории.
