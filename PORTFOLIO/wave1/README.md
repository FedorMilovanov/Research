# Волна 1: `mp3telegrambot` и `video-channel-manager`

Дата: 01.11.2026. Задача: применить контур `security-baseline` к двум репозиториям,
не сломав их собственные контракты.

Итог двух репозиториев оказался **разным**, и это главный результат волны:

| Репозиторий | Что показала проверка | Действие | Состояние |
|---|---|---|---|
| `mp3telegrambot` | все элементы контура уже есть, часть — строже шаблона | никакого | закрыто, изменений не требуется |
| `video-channel-manager` | отсутствует ровно один контроль — сканирование секретов | патч из одного файла | **готов и проверен, не отправлен** (нет прав записи) |

## Почему это не «поставить одинаковый шаблон в два места»

Слепое копирование шаблона сломало бы CI в обоих репозиториях:

* в `video-channel-manager` действует `tests/_workflow_actions.py`: каждое внешнее
  действие обязано быть 40-hex SHA **и** иметь комментарий версии (`# v7.0.1`),
  иначе `ActionPinError`. Шаблонный workflow ставит SHA без комментария — тест падает.
  Кроме того, `test_single_source_of_truth_publication_runtime_is_pinned_consistently`
  требует единой версии действия по всем 32 workflow, а `test_ref_binding_inventory`
  требует, чтобы любой `*_REF`/`*_BRANCH` в workflow был объявлен защищённым;
* в `mp3telegrambot` действует реестр `ACTION_PINS` из восьми действий с точными SHA
  и тегами: любое девятое действие = падение теста, `-latest` раннеры запрещены,
  `permissions:` обязательны в каждом файле.

Патч для `video-channel-manager` написан под эти ограничения и проверен их же тестами,
а не «на глаз».

## Блокер: права записи

Пуш в репозитории, отличные от `Research`, из этой сессии невозможен:

```
git push origin arena/576cf1ae-video-channel-manager
remote: Permission to FedorMilovanov/video-channel-manager.git denied
fatal: ... The requested URL returned error: 403

gh api -X POST repos/.../git/blobs
gh: Resource not accessible by integration (HTTP 403)
```

Чтение при этом работает (`gh api repos/...` возвращает `admin: true`), а запись
блокирует уровень интеграции, а не права пользователя. Поэтому волна 1 остановлена
на границе «файл готов, проверен, лежит в `Research`» — это проверяемое состояние,
а не обещание. Разблокируется одним из двух способов: выполнить `apply.sh` и пуш
вручную, либо выдать сессии GitHub-доступ к остальным репозиториям.

## Что дала волна помимо патча

1. **Проверка оказалась полезнее установки.** Из двух репозиториев контур был нужен
   одному, и ровно в одном месте. Формулировка «внедрено в 2 репозитория» была бы
   ложной: в одном нечего внедрять.
2. **Контракты репозиториев сильнее шаблона.** Там, где есть тесты пинов, шаблон
   избыточен: он проверяет форму ссылки, тест — конкретный отревьюженный SHA и версию.
   Поэтому джоб гигиены в патч не включён.
3. **История важнее диффа.** Недельный полный обход истории нужен именно потому,
   что «секрет добавлен и удалён» невидим на `pull_request`; проверка 3 194 коммитов
   по шести формам токенов до включения блокирующего гейта — часть подготовки, а не
   формальность.
