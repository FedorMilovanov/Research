# GitHub-поиск и заполнение профиля: что работает, а что миф

Короткий ответ на вопрос «само приходит или надо заполнять»: **наполовину само, но только после того, как заполнено индексируемое**. GitHub ищет по имени репозитория, описанию, topics и тексту README — не по коду и не по папкам. Пока эти поля пустые, искать нечего, и никакая активность не поможет. Звёзды и внешние ссылки сами не появляются никогда: это отдельная работа, а не следствие коммитов.

---

## 1. Как на самом деле ищет GitHub

| Что ищет | По чему ранжирует | Что это значит для тебя |
|---|---|---|
| Репозитории | имя, описание, topics, текст README (и файлы), звёзды, свежесть push | описание + topics + первый экран README дают попадание; звёзды дают позицию |
| Профили | имя, bio, location, компания, популярность репозиториев | bio и location обязательны; без них тебя нет в поиске людей |
| Topics-страницы | точное совпадение topic | topic «astro-ssg» приведёт людей из каталога темы |
| Google | README, GitHub Pages, внешние ссылки на репозиторий | README читается как страница; ссылки с сайта и статей весят больше всего |

Порядок влияния факторов, если по-честному: **внешние ссылки и звёзды > точное совпадение слов в имени/описании/topics > свежесть > размер репозитория**. Коммиты и объём кода на позицию почти не влияют.

Отдельно: GitHub **не** учитывает содержимое кода в поиске репозиториев (есть отдельный code search, но он требует входа и почти не приносит внешнего трафика).

### Уровень 3 — постоянно, даёт настоящий трафик

| Действие | Эффект |
|---|---|
| Ссылка на GitHub из футера каждого сайта | постоянный поток «referrers» и внешние ссылки для Google |
| Ссылка на репозиторий в описании YouTube-видео и в закреплённом комментарии | самый недооценённый канал для медиа-проектов |
| Одна статья с разбором метода (Хабр, dev.to, Medium, Reddit r/webdev, HN) | десятки звёзд за раз, если попадёт в тему |
| 2–3 собственных PR в чужие проекты (например, `alphacep/vosk-tts`, `pagefind`) | контрибуции видны в профиле и приносят переходы |
| Awesome-листы: `awesome-astro`, `awesome-telegram-bots`, `awesome-static-analysis` | долгоживущий источник переходов |
| Ответы на Stack Overflow с ссылкой на репозиторий (по делу, не спам) | трафик годами |

## 4. Профиль: как выглядит «правильно заполненный»

1. Аватар + имя + bio + локация + ссылка на сайт — заполнено полностью.
2. Profile README: 25–40 строк, первые 6 строк — кто ты и что работает (ссылки). Ниже — цифры и принципы работы.
3. Шесть закреплённых репозиториев: три «продукта», две «платформы», один «метод».
4. У каждого закреплённого — описание, topics, social preview, лицензия, README с блоком владельца.
5. Ни одного пустого или брошенного репозитория на витрине (`baptist*` — в архив).
6. Активность видна: последний push не старше двух недель (сейчас так и есть).

## 5. Про «само приходит»: три честных сценария

| Сценарий | Что происходит | Срок |
|---|---|---|
| Только заполнил профиль и topics | появляешься в поиске по своим терминам, 0–5 просмотров в неделю | 1–3 недели на индексацию |
| Заполнил + одна статья с реальным разбором | 20–200 звёзд на 1–2 репозитория, если тема попала | 1–2 месяца |
| Заполнил + статьи + PR в чужие проекты + ссылки из видео и с сайтов | устойчивый поток: 100–500 звёзд, приглашения, входящие заказы | 3–6 месяцев |

Звёзды не появляются от объёма кода. Единственная валюта — **польза для чужой задачи**: «как я сделал браузерный TTS без бэкенда» читают, «мой пет-проект» — нет.

## 6. Как измерять

- **GitHub → Insights → Traffic** на каждом репозитории: views, clones, referrers. Смотреть раз в две недели, не чаще.
- **Google Search Console** для `gospod-bog.ru`, `milovicake.ru`, `thelegendarypoet.ru`, `french.milovicake.ru` — там видно, по каким запросам находят сайты.
- **UTM-метки** на ссылках из статей и видео, чтобы отличать источники.
- **Простая таблица** в `Research/PORTFOLIO/`: дата, репозиторий, views, referrers, звёзды. Через месяц будет видно, что работает.

## 7. Антипаттерны

| Плохо | Почему |
|---|---|
| Набивать description ключевыми словами | выглядит как спам, GitHub может понизить; люди не кликают |
| Ставить 20 общих topics | каталоги тем перегружены, попадания нет |
| Покупать звёзды | риск блокировки аккаунта и репутационный ущерб |
| Дублировать репозитории под разные ключевые слова | размывает профиль, выглядит как накрутка |
| Держать пустые репозитории | «не довёл» — худший сигнал для нанимающего |
| Писать README для себя, а не для читателя | рекрутер читает 20 секунд; твои README сейчас написаны для агентов |
