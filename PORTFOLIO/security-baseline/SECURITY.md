# Безопасность

## Как сообщить об уязвимости

**Не создавайте публичный issue.** Используйте приватный security advisory:

`https://github.com/FedorMilovanov/{{REPO}}/security/advisories/new`

В сообщении полезно указать: затронутый модуль или страницу, шаги воспроизведения, влияние (утечка данных, выполнение кода, отказ в обслуживании, нарушение прав) и версию или коммит.

Ответ — в течение недели. Проект личный, поэтому сроки «как можно быстрее», без SLA.

## Поддерживаемые версии

Поддерживается только текущий `main`. Отдельных LTS-веток нет: исправления выходят вперёд, а не бэкпортируются.

## Что считается секретом

| Категория | Примеры | Где живёт |
|---|---|---|
| Токены провайдеров | `*_TOKEN`, `*_API_KEY`, `*_SECRET` | `.env` (в `.gitignore`, никогда в git) |
| Cookies и сессии | `cookies.txt`, `*.session` | рантайм-каталог (в `.gitignore`) |
| Ключи и сертификаты | `*.pem`, `*.key`, `*.p12` | вне репозитория |
| OAuth-клиенты | `client_secret*.json` | вне репозитория, абсолютный путь в конфиге |

Правила, которые действуют во всех проектах:

- Секрет не попадает в git — ни в код, ни в тест, ни в документацию, ни в CI-лог.
- Скрипт не зависит от текущего каталога: путь к секрету разрешается абсолютно, иначе запуск из чужого каталога читает не тот файл.
- Замаскированные значения печатаются только после проверки, что маска не содержит хвоста токена.
- Отозванный или скомпрометированный токен заменяется, а не «перепроверяется».

## Что делать при утечке

1. Немедленно отозвать секрет у провайдера — до любых правок кода.
2. Проверить журналы использования за период, когда секрет был доступен.
3. Удалить секрет из истории (`git filter-repo`) **после** отзыва; переписать историю без отзыва бессмысленно.
4. Записать разбор: где утёк, почему гейт не поймал, какой гейт добавлен.
5. Добавить случай в `LESSONS.md`/`CLOSURE_LEDGER`, если это повторяющийся класс.

## Автоматические проверки

- `security-baseline` workflow: `gitleaks` по всей истории, аудит зависимостей, гигиена workflow.
- Dependabot: еженедельные PR, без автомержа.
- Push protection и secret scanning — настройка репозитория (см. `CHECKLIST.md`).
