# Публикационный лейн — как из текста получается пост

**Проект:** SUNO-HYMNS-NL, канал «Господь Бог — Сила Моя» (`lord-god-strength`).
**Кому читать:** любому агенту, который готовит название, описание, закреплённый комментарий, пост в Telegram или теги для гимна этого проекта.

Этот файл отвечает на один вопрос: **что где лежит и что здесь нормативно, а что заимствовано**. Он не пересказывает правила разметки — он указывает, где они и как проверить, что они соблюдены.

---

## 1. Граница с репозиторием `video-channel-manager`

Два репозитория не конкурируют, у них разные предметы.

| Что | Где нормативно | Что делать агенту |
|---|---|---|
| Разметка описания и комментария YouTube (`*жирный*`, `_курсив_`, `-зачёркнутый-`), пунктуация внутри обёртки | `video-channel-manager/docs/youtube-description-rendering-standard.md`, § 2–3, § 11–12 | прочитать перед первой правкой копии; локально **не переписывать** правило |
| Выдача готового текста владельцу для ручной вставки — всегда в блоке `text`, чтобы `*` и `_` остались видны | там же, § 2 (последний абзац) | отдавать код-блоком, никогда цитатой |
| Состав и оформление комментария канала: факт → вопрос → компактный блок ссылок, лимиты, запреты, `project_key` | `video-channel-manager/docs/youtube-comment-editorial-standard.md` | сверить перед публикацией комментария |
| Общие требования к копии канала | `docs/youtube-copy-authoring-standard.md`, `docs/youtube-editorial-standard.md`, `docs/youtube-share-preview-standard.md` | только по нужде конкретной задачи |
| **Факты о гимне, источники, claim ledger, досье, черновики копий, гейт разметки** | **этот репозиторий** | работаем здесь |

**Почему не дублировать правила сюда.** Один нормативный текст в двух местах расходится через месяц, и следующий агент читает устаревшую копию. Здесь лежит только то, что проверяется машиной (`scripts/check_youtube_markup.py`) и то, что относится к этому проекту: факты, цитаты, статусы, ловушки.

**Если правила в `video-channel-manager` изменились** — меняется только тот репозиторий; здесь правится максимум ссылка на раздел. Обратное неверно: этот файл не вправе отменять стандарт канала.

## 2. Три файла копии для DUTCH-005

| Файл | Что внутри | Разметка |
|---|---|---|
| `DUTCH-005_YOUTUBE.md` | название, описание, tags, чек-лист, разбор прошлых ошибок | YouTube: `*жирный*`, `_курсив_` |
| `DUTCH-005_TELEGRAM.md` | пост для @lordchrist и HTML-двойник | Telegram: `**жирный**`, `*курсив*` |
| `DUTCH-005_PINNED.md` | два закреплённых комментария | YouTube: `*жирный*`, `_курсив_` |

Это **разные языки разметки**, и это главная ловушка лейна. Одиночная `*` в Telegram — курсив; двойная `**` в YouTube — две печатающиеся звёздочки. Копия не переносится из файла в файл без переразметки.

## 3. Порядок работы

1. Текст гимна — `DUTCH-005_LYRICS.md` (ревизия) и `DUTCH-005_LYRICS_SUNO.md` (с тегами). Правки только по указанию владельца, с записью в changelog.
2. Факты для копии — из `RESEARCH/CLAIM_LEDGER.md` и досье. Каждое утверждение в описании имеет названный источник; сниппет поисковой выдачи источником не считается.
3. Копия — в три файла выше, по одному на площадку.
4. Прогнать гейты (ниже). Падение гейта — не повод удалять разметку, а повод поставить знак внутрь обёртки.
5. Отдать владельцу **код-блоком**, не цитатой.
6. Публикация — вручную владельцем. Агент не публикует и не ставит статус «опубликовано» без проверенной ссылки.
7. После публикации: записать URL в `STATUS_LEDGER.md` и только тогда менять состояние на `PUBLISHED_VERIFIED`.

## 4. Гейты

```
python SUNO_HYMNS/scripts/check_youtube_markup.py <файл>        # разметка описания/закрепа
python SUNO_HYMNS/scripts/check_revision_consistency.py         # проза против файлов
python SUNO_HYMNS/scripts/validate_project_registry.py          # реестры и перекрёстные ссылки
python SUNO_HYMNS/scripts/check_ru_lyric.py SUNO_HYMNS/SUNO/*LYRICS*.md
```

Все четыре запускаются в CI (`.github/workflows/suno-hymns-registry.yml`). Гейт разметки вырезает блоки в тройных обратных кавычках из `DUTCH-005_YOUTUBE.md` и оба блока из `DUTCH-005_PINNED.md` и проверяет их по отдельности: закреплённых комментариев должно быть ровно два, каждый — чистый.

**Что именно ловит гейт:** закрывающая `*` или `_` не перед пробелом или концом строки; `**`; одиночная `*` в непарном виде; разметка в первом абзаце (он показывается свёрнутым); Markdown-ссылки вместо открытых URL.

## 5. Ловушки, на которых уже терялись

1. **Отдать копию цитатой в чат.** Чат отрисовывает `*…*` в жирный, звёздочки исчезают, владелец получает текст без разметки и не может его скопировать. Только код-блок.
2. **«Починить» разметку удалением разметки.** Уже было отвергнуто владельцем. Чинится знаком внутри обёртки.
3. **Перенести телеграмную `**` в YouTube.** Там она печатается буквально.
4. **Придумать нумерованные подзаголовки** «1. Где и когда… 2. Как устроен текст…». Этого никто не просил; вместо них — жирные зачины внутри абзацев.
5. **Арифметика дат.** 1679-й — через **два года** после смерти 1677-го, не за восемь.
6. **Считать, что гимн написан для богослужения.** Он написан для домашнего кружка; это и есть его главный факт.
7. **Считать мелодию найденной.** `Voyse: Un jour &c.` — не та «Un jour», что над текстом 27.

## 6. Статусы: копия готова ≠ опубликовано

`DUTCH-005` находится в состоянии **LYRIC_DRAFT**: тексты копий существуют, ничего не сгенерировано, не выбрано, не опубликовано. Ни один файл этого лейна не даёт права писать «вышло», «опубликовано» или «проверено», пока нет ссылки.
