# Бытие 6: нормализация физических путей файлов

**Дата:** 24 июля 2026 года  
**Статус:** `MARATHON-XLII / ROOT-NAVIGATION-NOTICE / FILE-LOCATION / PRESERVE-HISTORY / NO-DUPLICATE-OWNERS`

---

# 1. Обнаруженная особенность

Большинство новых материалов серии хранится в:

```text
ТРУДНЫЕ ТЕКСТЫ/
```

Но три артефакта марафона XXXIX были исторически созданы в корне репозитория:

```text
00_GENESIS6_MARATHON_XXXIX_WATCHERS_TERMINOLOGY_CORRECTION_NOTICE.md

ARTICLE_7_DANIEL4_WATCHER_TERM_AND_GENESIS6_TRANSFER_AUDIT_XXXIX.md

ARTICLE_7_WATCHER_TERMINOLOGY_67_SOURCE_VERIFICATION_MANIFEST_XXXIX.md
```

Это реальные файлы, а не отсутствующие документы.

---

# 2. Решение

Не создавать дубликаты этих owners внутри `ТРУДНЫЕ ТЕКСТЫ`, поскольку два одноимённых содержательных файла в разных местах создадут новый конфликт версий.

Не перемещать их destructive-операцией без отдельного lossless migration pass, поскольку на них могут ссылаться чаты, коммиты и другие документы.

Использовать:

- root-файлы XXXIX по их фактическим путям;
- `ТРУДНЫЕ ТЕКСТЫ/00_GENESIS6_MASTER_AUTHORITY_INDEX_AND_SUPERSESSION_MAP_XLII.md` как единую логическую точку входа;
- root `README.md` как пользовательскую навигацию.

---

# 3. Правило для будущих файлов

Все новые материалы этой серии создавать только в:

```text
ТРУДНЫЕ ТЕКСТЫ/
```

Исключения:

- корневой README;
- корневой навигационный redirect/notice;
- общерепозиторные аудиты, не принадлежащие одной тематической папке.

---

# 4. Будущая миграция

Если будет принято решение физически перенести XXXIX-файлы:

1. прочитать полный файл;
2. создать идентичную копию в тематической папке;
3. проверить SHA-256 содержимого без учёта пути;
4. обновить все внутренние ссылки;
5. заменить корневой файл коротким redirect notice или удалить только после проверки ссылок;
6. зафиксировать old path → new path в migration ledger.

До такого прохода действуют реальные корневые пути.
