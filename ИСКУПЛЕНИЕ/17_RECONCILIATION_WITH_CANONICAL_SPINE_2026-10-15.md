### 15. Аудит топологии: где на самом деле плодятся ветки (2026-10-22)

**Метод дороже чисел.** До сегодня песочница была shallow: история обрывалась на 286 коммитах, `git merge-base`
возвращал пусто, и git объявлял любые две ветки несвязанными — то есть каждый мой «hazard» был свойством среды.
`git fetch --unshallow origin` (29 MiB → 37 MiB, 2 216 коммитов) даёт другую картину:

| что стояло в §10c и в реестре | что меряется рабочим git'ом |
|---|---|
| «общего предка с `main` у них нет» | предок есть: `a01664c8` (мердж #215, 14.10), 1 956 общих коммитов |
| squash их ветки: 48 файлов, −7 913, из них 30 удалений `ot/` | их дельта от своей базы: 16 файлов, +2 797 / −5, удалённых файлов 0, `ot/` они не касались |
| merge-commit: 16→17 add/add, с #216 — 20→21; реестр в дереве — битый JSON | `git merge-tree` тех же концов: 0 конфликтов, и с моим PR тоже 0; JSON валиден |

Механика подмены: `git diff origin/main..B` (две точки) — разница деревьев, в неё попадает всё, чего у `B` нет,
потому что `main` уехал вперёд; PR так не считается, PR — это `main...B` от реальной базы. Правило записано в
`branchTopologyAudit20261022.howRule`: любой git-замер про чужую ветку начинается с `git rev-parse
--is-shallow-repository` = false и непустого `merge-base`; слово `unrelated` в §10c остаётся как имя артефакта.

**Дно.** В `origin` **26** ветвей, **один** корень (`8131f3c2`, «Initial commit», 26.06), удалённых
файлов — **0** во всей системе. **8** уже в `main` (их tip — предок main), **18** нет. Полная
таблица — 26 строк × 14 колонок — лежит в `branchTopologyAudit20261022.rows`, здесь только раскладки, сочтенные
из той же таблицы: содержимое целиком уже в `main` blob-в-blob у **4** веток (четыре
`research/apostasy-*` с закрытыми PR — работа влита другим путём), почти целиком ещё у **2**
(`teen-double-life` 298 из 299, `covenant-children` 321 из 323). С конфликтами с нынешним `main` — **9** веток, всего **33** `add/add` и **10** `content`; треть налёта даёт одна
брошенная волна `agent/le-canon-sucre…` (21 `add/add`, +4 168 строк, PR #154 закрыт 09.08, в main — ни строкой).
