**Product inspected:** `FedorMilovanov/gb-is-my-strength`, shallow clone сделан 2026-10-07 (локально, вне репозитория Research; точный head не пинится, потому что это не release-witness)

## 1. Что реально есть в Product (проверено по коду, а не по памяти)

1. **Content-модель.** `src/content/articles/*.mdx` cо схемой из `src/content.config.ts`: обязательны `title` (8–120), `description` (40–220), `slug` (`^[a-z0-9-]+$`), `section` из **жёсткого enum** `['articles','biografii','hard-texts','nagornaya','baptisty-rossii']`, `publishedAt`/`updatedAt`, `series?`, `tags[]`, `related[]`, `sourcesRequired` (по умолчанию `true`), `sourceMode`, `draft`, `noindex`.
2. **Series hubs верхнего уровня** уже существуют как тип страницы: `window.SITE_CONFIG.page.type = 'series'`, JSON-LD `CollectionPage` с `hasPart[]` и `BreadcrumbList` (проверено в `hard-texts/index.html`, где hub = «Тайны человеческого сердца»).
3. **Порядок статей внутри серии** задаётся не содержимым файлов, а `SERIES_ORDER` в `src/data/site.ts` (проверено: `hard-texts`, `dzhon-gill`, `pastor-series`, `genesis-6`, `teen-double-life`…).
4. **Публикационная принадлежность route** управляется `data/route-search-policy.json` (104 route на момент проверки) + `data/route-profiles/*.json` + `migration/page-ownership.json` → `scripts/lib/effective-route-registry.js` → производная `migration/route-migration-matrix.json` (её руками не правят).
5. **Поиск.** Pagefind + `data/search-manifest.json` как проверяемая проекция; для статей есть `topicCategory`/`librarySection`. **Тематического раздела «Искупление» в реестре нет**; ближайший — `/hard-texts/` (сердце) и статьи о Gill/Джоне Гилле.
6. **Глоссарий и оригинальные слова** — отдельные данные: `data/glossary.json` (записи вида `definition/detail/aliases/category/categorySlug`) и `data/original-words.json` (49 записи: `original/lang/transliteration/gloss/definition/source`). **Ни `ἱλασμός`, ни `λύτρον`, ни `ἀπολύτρωσις` там нет** — то есть поисковый и терминологический слой для этой темы физически отсутствует.

Вывод: сайту не нужен новый content-framework. Нужны (а) новый series hub, (б) статьи, (в) регистрация route-профилей и поисковой принадлежности, (г) терминологический слой в глоссарии и `original-words`.

## 2. Рекомендуемая публичная структура

### Hub

**Route:** `/redemption/`
**Reader-facing название:** «Искупление: для кого умер Христос» (рабочее; окончательное — на `W6`)
**Тип:** `page.type = 'series'` + JSON-LD `CollectionPage`/`hasPart`.

Почему route на латинице: соответствует существующим коротким тематическим routes (`/hard-texts/`), стабилен при переименованиях русских заголовков, не несёт полемического ярлыка. Русский читатель видит заголовок, а не slug.

Альтернатива (если владелец предпочитает единый стиль русских slug'ов): `/iskuplenie/`. Решение — за Product-lane; в обоих случаях **нужен явный `contentConfig`-вывод**: `section` enum в `src/content.config.ts` **не допускает** новое значение без изменения схемы, то есть hub — это не «добавить mdx», а `SYSTEM`-lane с правкой schema + навигации.

## 3. Обязательное содержание hub'а

1. **Hero** — название + 2–4 предложения о том, что исследуется (не «опровергается»).
2. **Doctrinal orientation**: различение `O-1…O-6` (`04_...` §1) в человеческом языке: ценность / намерение / действенность / предложение.
3. **Series map**: карточки с статусом («готово» / «в работе») и временем чтения.
4. **Определения**: «искупление», «умилостивление», «примирение», «выкуп», «достаточность/действенность» — короткие, с tooltip-ссылками на глоссарий.
5. **Two-columns panel**: «тексты о “всех”» и «тексты о “своих”» — с явной задачей: объяснение должно покрывать оба столбца.
6. **Research note**: первичные тексты проверяются по изданиям; русские переводы исторических авторов — редакционные, где нет установленного русского издания; библейский текст — по Синодальному переводу (после закрытия `BIBLE_CORPUS`-зависимости).
7. **Crosslinks** на реально полезные материалы: `/hard-texts/` (сердце), Gill-серия (offer/учение Гилла), «Трудные тексты» (Бытие 6 / Иуда — только при наличии мостика: 2 Петра 2). Hub не должен превращаться в каталог ссылок.

## 4. Внутренняя навигация статьи

- breadcrumb: Главная → Статьи → Искупление → текущая статья;
- series-badge над H1;
- `thesis box` сразу после введения, но **без вывода до экзегезы**;
- TOC (desktop — sticky, mobile — существующий reader TOC);
- **обязательный блок «Что здесь не утверждается»** (по правилу `04_...` §4.5) — для темы, где читатель достраивает выводы сам;
- «В серии» prev/next;
- source notes: по изданию и странице; для Писания — перевод и издание;
- семантические внутренние ссылки внутри текста, не только в конце.

## 5. Поиск, глоссарий и терминологический слой (это и есть «новый поисковый отдел»)

Чтобы тема была находимой, а не просто выложенной, Product-lane обязана сделать пять вещей:

1. **`data/route-search-policy.json`** — записать hub и каждую статью: `indexPolicy: index`, `pagefindPolicy: include`, `searchManifestPolicy: include`, `sitemapPolicy: include`, `rssPolicy: include|exclude`, `contentKind: series|series-article`, `librarySection`, `topicCategory: "Искупление"`.
2. **`data/route-profiles/*.json`** — по профилю на каждый новый route (`articles-za-kogo-umersya-hristos.json` и т. д.) и профиль hub'а.
3. **`migration/page-ownership.json`** → затем `node scripts/sync-route-migration-matrix.js --write` и `npm run migration:metadata:check:strict` (матрица — производная, руками не правится).
4. **`data/glossary.json`** — добавить записи: `искупление`, `умилостивление`, `примирение`, `выкуп`, `достаточность и действенность`, `определённое (частное) искупление`, `всеобщее (неограниченное) искупление`, `гипотетический универсализм`, `умилостивительная жертва? / удовлетворение`, `замещение`. Формат — как у существующих записей: `definition` (1 предложение), `detail` (абзац с примерами и ссылками на тексты), `aliases`, `category`, `categorySlug` (новая категория «Сотериология» — проверить, есть ли она уже в glossary-policy).
5. **`data/original-words.json`** — добавить lexeme-записи: `λύτρον`, `ἀντίλυτρον`, `ἀπολύτρωσις`, `ἀγοράζω`, `ἐξαγοράζω`, `ἱλάσκομαι`, `ἱλασμός`, `ἱλαστήριον`, `καταλλαγή`, `πολλοί`, `πᾶς`, `κόσμος`, `כָּפַר`, `גָּאַל`, `פָּדָה` — по схеме `{original, lang, transliteration, gloss, definition, source}`, где `source` = конкретное издание словаря и статья. **Заполняется только из проверенных лексических карточек `W1`** (`03_...` слой L): ни одна строка не появляется «по памяти».

Дополнительно, если hub вводится как новая value в `section` enum: обновить `src/content.config.ts`, все consumers enum'а, `data/site.ts` (`SECTION_META`, `SERIES_ORDER`), навигацию, `llms.txt`, sitemap/RSS-генерацию и тесты на metadata; и прогнать соответствующие Product-проверки (build/accessibility/internal links/search manifest).

## 6. SEO/metadata plan

**Hub `/redemption/`**
`title`: «Искупление: для кого умер Христос — библейское исследование | Господь Бог — Сила Моя»
`description`: «Что Библия называет искуплением, как различать ценность, намерение, действенность и предложение — и что тексты о “всех” и о “своих” говорят на самом деле.»
`og:image`: новый OG-шаблон серии (по образцу `images/og-series-heart.webp`) — генерировать только с проверенными правами на исходник.

**Принцип заголовков.** В `title` и `h1` — вопрос читателя, а не ярлык полемик (`«Опровержение всеобщего искупления»` — запрещено редакционным решением; `«За кого умер Христос?»` — допустимо). Ключевые слова: «искупление», «за кого умер Христос», «ограниченное искупление», «всеобщее искупление», «умилостивление», «искупление в Кальвинизме», «1 Ин. 2:2», «2 Петра 2:1», «Мк. 10:45», «Дортский синод». При этом `keywords` не должны создавать иллюзию, что статья — polemic hit-piece.

## 7. Telegram/Teletype

- **Teletype** — не canonical source. Допустима адаптация hub-orienting эссе со ссылкой на канонический article.
- **Telegram** — один текст/одна мысль, 3500–4000 знаков, ссылка на canonical article, максимум 1–2 проверенные цитаты из первоисточников. Для этой темы это особенно важно: в Telegram-формате extent-спор мгновенно деградирует в лозунг.

1. **Статья 1** (термины) + **hub в «черновом» режиме** — как только `W1` закрыт.
2. **Статья 7** (Дорт) — короткая, документально сильная, задаёт тон «мы читаем первоисточники».

4. **Статьи 4, 5, 10** (текстовые) — ядро экзегезы.
5. **Статьи 3, 8, 9** (богословские/исторические) — глубина.

Hub индексируется не раньше, чем готовы минимум две статьи (политика «не индексировать полупустую серию», перенесённая из практики `../apostasy/07_...`).

## 9. Что обязано произойти до переноса в Product

1. Все переносимые досье — `PUBLICATION-CANDIDATE`, с `0` непроверенных цитат и с закрытыми `LOCATOR_HOLD`.
2. Библейские цитаты — только после закрытия `../BIBLE_CORPUS/`-зависимости (иначе — пересказ).
3. Product-lane: отдельный owner, branch + PR, режим по `docs/WORK_MODES.md`; точные проверки по `AGENTS.md` (build, metadata strict, accessibility, internal links, search manifest).
4. Никаких «временных» цитат Мюррея/Owen по вторичным сайтам: если локатор не закрыт — цитата заменяется пересказом с атрибуцией «по изданию, страница не сверена» — или не публикуется вовсе.
5. После source merge — отдельный live-witness release (страницы, metadata, поиск, print, no-JS); source merge не доказывает live bytes.
