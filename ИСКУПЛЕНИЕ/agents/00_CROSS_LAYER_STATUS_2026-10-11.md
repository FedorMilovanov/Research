## 3. Проверка слияния: 0 конфликтов

Проверено `git merge-file --diff3` (трёхстороннее слияние: base = `main` `eee4624`, ours = HEAD этой ветки, theirs = HEAD каждой чужой ветки) по всем файлам, которые правит более чем одна ветка:

```
data/atonement-corpus-v1.json               vs 210 / 211 / 212 / 213 → 0 / 0 / 0 / 0
```

**Один конфликт был найден и устранён в этой ветке** (коммит `f098513`): `00_README_AND_NAVIGATION.md` против #210. Причина — обе ветки дописывали в конец одного и того же нумерованного списка. Устранено переносом наших дополнений в отдельный ненумерованный блок в зоне, которую не правит никто; строка п. 16 возвращена к тексту `main`. Подробности и обоснование — в самом файле.

> **Предупреждение тем, кто будет править `00_README` дальше.** Все четыре ветки правят одну и ту же зону: сразу после п. 16 и сразу после строки «Машинный локальный реестр». Любое добавление в эту зону с любой стороны даст конфликт. Дописывайте в ненумерованные блоки вне зоны.

**Проверка повторяемая.** Одной командой:

```bash
git fetch -q origin '+refs/heads/*:refs/remotes/origin/*'
for f in 00_README_AND_NAVIGATION.md 05_SOURCE_REGISTRY_AND_ACQUISITION_QUEUE.md \
         12_HARD_TEXTS_EXTENT_CARDS.md 13_DORT_II_CALVIN_OWEN_EXTENT.md \
         14_OWEN_DEATH_OF_DEATH_BOOK_IV_LOCATORS.md 15_CALVIN_III24_AND_DORT_II_LOCATORS.md \
         00_CURRENT_AUTHORITY_2026-10-07.md data/atonement-corpus-v1.json; do
  git show "main:ИСКУПЛЕНИЕ/$f" > /tmp/base.md
  cp "ИСКУПЛЕНИЕ/$f" /tmp/mine.md
  for b in 13e971a8 9269c042 b1e47718 5fe5b33f; do
    git show "origin/arena/$b-research:ИСКУПЛЕНИЕ/$f" > /tmp/theirs.md 2>/dev/null || continue
    n=$(git merge-file -p --diff3 /tmp/mine.md /tmp/base.md /tmp/theirs.md 2>&1 | grep -c '^<<<<<<<')
    [ "$n" != 0 ] && echo "CONFLICT $f vs $b : $n"
  done
done
```

Пустой вывод — чисто. Запускать **перед** каждым пушем в эту ветку и перед финальным мержем.
