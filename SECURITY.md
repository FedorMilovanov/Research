# Безопасность

Репозиторий содержит исследовательские материалы и скрипты сбора данных. Здесь нет пользовательских данных, но есть учетные данные внешних источников (Google Drive, архивные и библиотечные API, GitHub).

## Как сообщить об уязвимости

**Не создавайте публичный issue.** Используйте приватный security advisory:

`https://github.com/FedorMilovanov/Research/security/advisories/new`

Укажите: затронутый скрипт или workflow, шаги воспроизведения, влияние (утечка токена, доступ к чужому источнику, изменение данных), коммит.

Ответ — в течение недели. Проект личный, поэтому сроки «как можно быстрее», без SLA.

## Что считается секретом

| Категория | Примеры | Где живёт |
|---|---|---|
| Токены источников | `*_TOKEN`, `*_API_KEY`, ключи архивных API | `.env` (в `.gitignore`), никогда в git |
| Сервисные учётные записи | `client_secret*.json`, `credentials.json` | вне репозитория, абсолютный путь в конфиге |
| Сессии и cookies | `cookies.txt`, `*.session` | рантайм-каталог |
| Приватные ключи | `*.pem`, `*.key`, `*.p12` | вне репозитория |

Правила:

- секрет не попадает ни в скрипт, ни в тест, ни в исследовательский документ, ни в лог CI;
- скрипт не зависит от текущего каталога: путь к файлу секрета разрешается абсолютно — иначе запуск из чужого каталога читает не тот файл;
- замаскированные значения печатаются только после проверки, что маска не содержит хвоста токена;
- при подозрении на утечку сначала отзывается токен, потом правится код. Переписывание истории без отзыва бессмысленно.

## Автоматические проверки

- `security-baseline.yml`: `gitleaks` (блокирует PR при находке в новых коммитах; недельный обзор истории — не блокирующий до разбора), гигиена workflow (пины, `permissions`, запрет `write-all`, `pull_request_target` только с проверкой форка, отсутствие файлов вида `.env`/`*.pem` в индексе), грубая проверка строк последнего коммита на формы токенов.
- Dependabot: обновления GitHub Actions, без автомержа.

## Граница ответственности

Репозиторий описывает чужие источники и цитирует их. Наличие URL не даёт прав на повторную публикацию материала; права и лицензии фиксируются в соответствующих authority-документах, а не здесь.
